# 系列企劃框架：一次規劃一整季 MV

中文 | [English](../../en/mv/SERIES_PLANNING.md)

一支 MV 照 [WORKFLOW.md](WORKFLOW.md) 做。要做一整個系列（例如一季 4–8 集），先用這份把整季規劃好，再一集一集做。

這是框架，不是範本。**公式**管的是「怎麼讓一季看起來是同一個系列」；**自由**留給「每一集講什麼、長什麼樣」。框架只規定要填哪些格子，不規定格子裡填什麼。空白範本在 [`examples/mv/series_template/`](../../../examples/mv/series_template/)。

| 公式（每一季都要有） | 自由（全部由你決定） |
|---|---|
| 一句話定系列 | 題材、形式、集數 |
| 一條主軸，把集數排成順序 | 用哪一條主軸、季終怎麼收 |
| 幾個固定的錨點 | 固定哪幾個、其他全部放開 |
| 整季同一個歌曲結構 | 用哪一種結構 |
| 整季同一套包裝（縮圖、標題、說明欄） | 包裝長什麼樣 |
| 每集一張企劃卡 | 卡片裡的故事、曲風、畫風 |

## 1. 一句話定系列

**公式**：`{題材} × {形式}，每集一個 {變數}`

- 「一個郵差 × 民謠流行，每集送一封信」
- 「七種天氣 × 女聲獨唱，每集一種天氣裡的分手」
- 「同一間老公寓 × 樂團，每集一個年代的住戶」
- 「末班車 × city pop，每集一個在不同站下車的人」

**自由**：題材、形式（獨唱、對唱、樂團、純音樂）、集數都不限。一句話講不清楚，通常是題材還太大。

## 2. 主軸：讓集數有順序

**公式**：找一個每集都會變的東西，讓它**往同一個方向**變。最後一集打破它，或完成它。

| 主軸 | 怎麼排 |
|---|---|
| 時間 | 一天的時刻、四季、一生的年紀、一段歷史 |
| 距離 | 兩個人越來越近，或越來越遠 |
| 強度 | 情緒或能量一集比一集強 |
| 選擇權 | 主角一集比一集更能替自己做主 |
| 規模 | 一個人 → 一個家 → 一座城 → 世界 |
| 倒敘 | 從結局往回講，最後一集是起點 |
| 拼圖 | 每集一塊線索，季終拼起來 |

**季終的三種收法**：翻轉（前面都做不到，最後一集做到）、完成（拼上最後一塊）、循環（最後一個鏡頭回到第一集的第一個鏡頭）。

- **每集用一個詞說完它在主軸上的位置。** 這個詞就是那一集的企劃，也可以當片頭字卡和章節小標。
- **下一季換一條主軸。** 同一個題材換主軸，就是新的一季。

## 3. 系列風格聖經：固定幾個錨點，其他放開

`style.md` 在第一集開工前先寫草稿，第一集做完再照成品定稿。之後每一集寫歌詞、寫 prompt、做縮圖之前，都先對照它。

**公式**：從下表挑 **3–5 個錨點**固定下來，其餘每集自由。

| 層 | 可以固定的錨點 | 可以每集換的 |
|---|---|---|
| 畫面 | 畫風、時段與光線、一個反覆出現的物件或場景、轉場形式、畫面比例 | 主色、場景、象徵物 |
| 角色 | 同一位主角、同一張臉、造型規則 | 身分、服裝 |
| 聲音 | 歌曲結構、人聲配置、一個聲音記號（同一件樂器、同一句哼唱） | 曲風、BPM、調性 |
| 字幕 | 字型、排版規則、關鍵字顏色 | 特效、哪些詞變色 |
| 包裝 | 縮圖版型、標題格式、說明欄順序 | hook、文案 |

- **包裝最該固定。** 觀眾在首頁第一眼認出系列，靠的是縮圖和標題。
- **一層固定，就讓另一層大換。** 畫面固定的話，就讓曲風每集換；曲風固定的話，就讓畫面每集換。每一層都固定，第三集就膩了。
- **固定的錨點太少**（只剩標題格式）看不出是系列；**太多**（畫面、角色、曲風全一樣）每集像同一支。
- **每集換的格子做成一張對照表，一次填完整季**，看看顏色、曲風、BPM 有沒有連續兩集撞在一起。
- **強調色只用在情緒高點**，不要蓋過系列的主色。

## 4. 歌曲結構：整季用同一種

結構固定下來，觀眾每集都會期待同一個位置發生的事。

**公式**：挑一種結構，整季沿用。

| 結構 | 怎麼用 |
|---|---|
| 問答 | 副歌一問，副歌二用同一段旋律回答，把問句翻過來 |
| 變形 hook | 每遍副歌同一句，最後一遍改一個字 |
| 章回 | 每一段是一個場景或時間點，像分幕 |
| 首尾呼應 | 每集開頭同一句，結尾每集不同 |

**自由**：段落長度、誰唱、語言、要不要有念白或純音樂段。

寫詞的通則：
- **主歌不要寫得太工整。** 每句字數一樣、押同一個韻，唱出來像念經；長短句、口語比較像人在說話。
- **引用（典故、名句、台詞）只放在副歌或轉折點**，其他地方用好懂的話。
- **歌詞照 Suno 格式寫**，存成每集的 `歌詞_v*.txt`：Title、Style、Exclude，加上帶標籤的 Lyrics。每段標籤寫清楚誰唱、什麼音色，例如 `[Verse 1: Male Vocal Only, Warm Tenor, Gentle]`，聲部才不會唱錯人。

## 5. 每集一張企劃卡

`research.md` 裡每集寫一張，欄位固定：

- **一個詞**：這一集在主軸上的位置
- **靈感與出處**：真實事件、典故、作品；有爭議的要註明
- **故事**：三到五句
- **情緒弧線**：五步以內
- **核心物件**：一件，拿來做縮圖和片頭
- **色調**：開場、轉折、結尾三段
- **曲風**：主曲風 × 一個對撞元素
- **最後一個鏡頭**
- **要查證的事**：之後寫進說明欄

整季的卡片先寫完，再寫第一首歌。寫卡片時常會發現兩集的物件或色調撞了，這時候改不用花點數。

## 6. 曲風：主曲風 × 一個對撞元素

**公式**：每集一個主曲風，再加一個從故事裡找來、跟主曲風衝突的元素（一件樂器、一種現場聲音、一種唱法、一種語言）。

- 主曲風照故事挑。衝突本身就是看點，例如 trap 配弦樂四重奏、合成器流行配教堂管風琴、lo-fi 配一段現場錄音。
- 對撞元素只留一兩個，當 hook 用；整首都塞滿，幾集聽起來會糊成一首。
- **自由**：也可以整季同一個曲風，改讓畫面每集大換（見第 3 節「一層固定，就讓另一層大換」）。

## 7. 串場與收束

- **讓一個物件或一句詞在兩集各出現一次**，看過前一集的人會認出來。
- **每集說明欄都連回第一集**，也寫明這是第幾集。
- **季終替下一季留一句。**

## 8. 角色

- **自由**：同一位主角貫穿整季，或每集換人都可以。
- 貫穿的話，把第一集的定裝圖放進每一集的 `ref/`，之後的定裝都從這張臉做，只換服裝和場景。
- **每集寫一份 `角色.md`**：定案的是哪張候選圖、哪套服裝用在哪些鏡頭、兩人能不能同框。
- **近景盡量單人**，兩人同框用遠景或背影。雙人近景的靜圖很難做穩（見 [LESSONS.md](LESSONS.md)）。
- **死亡、暴力等敏感畫面用物件和空景暗示**，不直接拍。

## 目錄與命名

```
projects/<系列名>/
  style.md                  系列風格聖經：固定的錨點、每集對照表、包裝格式
  research.md               一句話、主軸表、每集企劃卡、待確認清單（一季一節）
  s1e1_<歌名>/              s{季}e{集}_{歌名}：照順序排，跨季也排得對
  s1e2_<歌名>/
  s2e1_<歌名>/
```

每一集的資料夾：

```
s1e1_<歌名>/
  project.py          這一集的全部設定（見 PROJECT_FORMAT.md）
  歌詞_v1.txt …       改版就加版號，不覆蓋；style.md 的對照表寫明定稿是哪一版
  角色.md             定裝定案、服裝分配、同框規則
  YouTube_SEO.txt     標題、說明欄、章節、標籤
  thumbs.py           縮圖，照系列版型
  ref/                系列主角的定裝圖
  audio/ chars/ kf/ clips/ jobs/ out/ …      素材和生成檔
  kf_rejected/ clips_cand/                   被退的、候選的版本：搬過去，不要刪
```

- **只打算做一季，也一開始就用 `s1e1_`。** 之後開第二季不用改名。
- **資料夾在第一次送 AutoIP 任務之前定名。** 任務檔 `jobs/*.json` 裡寫的是絕對路徑，送出之後改名，續跑會找不到檔案。
- **被退的版本搬走，不要刪。** 之後要查為什麼退，才找得到。
- 素材（`ref/`、`chars/`、`kf/`、`clips/`、`audio/`、`out/`）都不進 git。

## 每一集的順序

1. 對照 `style.md` 和這一集的企劃卡，寫 `歌詞_v1.txt`。
2. 生成歌曲、聽過；改詞就另存 `v2`、`v3`。
3. 定裝，寫 `角色.md`，**給使用者確認**。
4. 第一集從 [`examples/mv/demo/project.py`](../../../examples/mv/demo/project.py) 開始；第二集起複製**上一集**的 `project.py`，改跟故事有關的欄位，字幕主題、縮圖版型、`EDITS` 的結構都沿用。
5. 照 [WORKFLOW.md](WORKFLOW.md) 做完：音訊、分鏡、關鍵影格、影片、品管、剪輯、字幕、合成。
6. 照 `style.md` 的包裝格式寫 `YouTube_SEO.txt`、做縮圖（[PUBLISHING.md](PUBLISHING.md)）。
7. 回頭更新：`style.md` 的對照表打勾、寫上定稿歌詞是哪一版；這一集踩到的坑記下來，通用的寫進 [LESSONS.md](LESSONS.md)。

## 上架前的一致性檢查

- [ ] `style.md` 裡固定的錨點，這一集都有
- [ ] 這一集換掉的那一層，跟前一集確實不一樣
- [ ] 歌曲結構跟前幾集同一種
- [ ] 縮圖版型、標題格式、說明欄順序跟前幾集一樣
- [ ] 說明欄連回第一集，寫明第幾集
- [ ] 要查證的事寫進說明欄
- [ ] 完整版和直式短版都做了

## 跟 agent 說

```text
用 dreamfab-mv 規劃一個 6 集的 MV 系列：<題材>
```

agent 會先問你題材、主軸和想固定哪些錨點，寫好 `research.md`（一句話、主軸表、每集企劃卡）和 `style.md` 給你確認，才開始做第一集。它不會套用任何現成系列的風格。

```text
照 projects/<系列名>/style.md 做第 3 集，從第 2 集的 project.py 開始
```
